# UI-аудит: что изменено, чем проверено и готово ли к UAT

```text
50 параллельных аудиторов → находки → воспроизведение RED → минимальный фикс
                                    │
                                    └→ независимое ревью → повторные проверки
                                                               │
                                      первый ручной UAT на копии данных
                                      ≠ проведённая пользовательская приёмка
```

## Вердикт

**Да — готово к первому ручному UAT основных пользовательских сценариев на отдельном
проекте и копии библиотеки. Нет — полная пользовательская/production-приёмка ещё не
проведена.** Автоматические проверки не заменяют работу человека с реальными PDF,
моделью, Zotero Desktop, аккаунтами и развёрнутым удалённым доступом.

Этот отчёт описывает последний цикл исправлений и проверенный рабочий код.
PR `pre-main → main` также содержит предшествующую работу ветки: его полный diff
не следует считать исключительно результатом UI-аудита. Изменения архитектуры,
которые уже были в рабочем дереве, сохранены, а не сброшены ради зелёных тестов.

## Что сделано и зачем

| Область | Проблема → решение | Как проверено |
|---|---|---|
| Архитектура и состояние | Закреплены границы `api → services → storage/integrations`; foundational runtime не импортирует сервисы. Сохранены миграции/история/контракты синхронизации. | Статические import/LOC/complexity-гейты и текущий полный Python-прогон. |
| Setup / Settings | AI и ML-only не смешиваются; сохранение не выдаётся за проверку. Исправлены локальный ввод модели до inventory, несовместимые профили, переходы к AI/RSS-настройкам и восстановление Doctor. | Unit/API/CLI и built-browser-проверки; реальные модели не загружались. |
| Native request / безопасность загрузки | Возврат callback или непустой текст не доказывает завершённый native-запрос. Неопределённое выполнение удерживается без автоматического повтора; одобренный policy-файл не заменяет наблюдаемый runtime envelope. | 26 проверок с установленными SDK, из них 6 с собственным TCP-сервером; негативные/late-completion/timeout-контроли. |
| Черновики и действия | Не теряются новые теги при ошибке/неопределённом результате/отказе force. Вход в university access использует подтверждённые сохранённые параметры. Feed Review проверяет точные ID и состояние ACK. | Удерживаемые ответы, старые callbacks, несовпадающие ACK, отказ и новый текст во время запроса. |
| Paper / Reader | Не выдаются устаревшие HTML/figures; отсутствующий опубликованный figure делает артефакт неполным. Rebuild привязан к paper/render, late callback не инвалидирует другую статью. | Реальные owned-файлы/API и текущие React-регрессии, включая A→B→A и старый запрос A после выбора B. |
| Вопросы и заметки | Composer доступен без PDF/review; сохранение вопроса отдельно от генерации ответа. Отмена ухода сохраняет грязный черновик; подтверждённая доставка не теряется при refetch. | API/IndexedDB/React и built-browser-сценарии offline/sync-first/потерянного ответа. Это не тест качества ответа модели. |
| Search / Discovery / MCP | Старый poll **и отдельный retry GET** не стирают подтверждённый Add. Retry не лишает полномочий уже выполняющиеся независимые Adds. Полные IDs/цитаты переносятся, а similarity требует непустой запрос и фактическое `semantic=true`. | Сначала воспроизведены оба interleaving; затем 79 Search-проверок. Built UI 390/1440, проверки геометрии и сохранности текста; MCP-негативные контроли. |
| Ops / Pending / клавиатура | Ошибка статуса не запускает retrain/generation повторно. Убран неверный backlog-start из Ops: этим владеет Today. Verdict-клавиши требуют точного загруженного detail. Добавлены native labels/section heading. | Unit/API, источник текущего job, удерживаемые статусы; actual Chromium DOM на двух ширинах. |
| Кэш / Weekly / публикация | Исходные доказательства проверяются до display projection; unknown не превращается в отрицательный результат. Публикация review, staging Pending и native ACK остаются разными событиями; резервные копии обязательны. | Producer→verifier→cache/worker/API, native SQLite, malformed/stale/missing/partial/uncertain-контроли. |
| Эксперименты | Interpretation остаётся opt-in и не просачивается в обычный кэш. Frozen support/priority/collection используют текущие контракты; declared lineage и полное покрытие разных вопросов не подменяются числом дубликатов. | Проверки протоколов, источников/байтов/состояний, replay и изоляции. Научная полезность не заявляется. |
| Регрессионные fixtures | Устаревшие DTO/imports/голые Mock receipts заменены актуальными владельцами и owned inputs, с сохранением исходных существенных оракулов. | Нет compatibility-фасадов, глобального waiver старых failures или удаления проверки только ради GREEN. |

[Все 67 записей находок и решения по ним](findings.json) сохранены отдельно:
это **не 67 независимых багов**. Среди них есть дубликаты, ошибки fixtures,
уже отсутствующая логика и неподтверждённые гипотезы. Например, незаявленный
Cancel/Delete CRUD для заметок не был добавлен как новая разрушительная функция;
существующие Save и подтверждение ухода с черновиком проверены.

Полезный контрпример к «тесты зелёные — значит всё работает»: ранний зелёный полный
прогон не покрывал несколько исходных UI-находок. Они были заново разобраны и
исправлены. Независимый reviewer затем нашёл ещё одну реальную гонку Search:
удерживаемый retry GET стирал уже подтверждённый Add. Сначала зафиксированы
`17 tests / 1 failure`, затем дополнительный sibling-owner контрпример
`18 / 2 failures`; после исправления — `79/79` в расширенной группе, reviewer
снял блокирующее замечание. Финальные 973 включают эти регрессии.

## Что ещё не проверено человеком / на реальной установке

| Область | Готовность |
|---|---|
| Основной UI, ML-only onboarding, capture/notes, recovery/offline | Готово к первому ручному UAT на отдельном проекте. |
| Реальные native-записи и Zotero Desktop | Сначала копия библиотеки и проверенная резервная копия; автоматический тест owned SQLite не равен принятию результата в native GUI. |
| Hosted/local AI и качество ответа | Не подтверждено реальным inference/корпусом. Протокольные тесты не доказывают полезность или научную достоверность. |
| Full-local Doctor / hardware capacity | При отсутствии authoritative executing-runtime envelope ожидается **UNKNOWN/refusal**. Не отключать защиту ради зелёного Ready; наличие модели/policy/свободной RAM недостаточно. |
| Telegram и private corpus | Account/dependency/private-input сценарии выше не исполнены. Авторизация/установка зависимостей/доступ к данным отдельно от этого аудита. |
| HTTPS remote deployment | Нужен отдельный owner-authenticated deployment smoke. Loopback/ASGI/тесты CORS не сертифицируют реальный gateway. |

**Решение о production-готовности — после ручного UAT.** Нет обещания exactly-once,
удалённого termination/cancellation, безопасности любых filesystem races,
аутентифицированной lineage или причинного улучшения модели.

## Чек-лист первого ручного UAT — ещё НЕ выполнен

Использовать отдельный project root и **копию** Zotero/PDF-данных. Первый проход —
ML-only, без аккаунтов и без загрузки LLM; реальные AI/native workflows расширять
только отдельным явным решением. Не проводить разрушительные или uncertain-replay
эксперименты на основной библиотеке.

| Шаг | Действие | Что принять как PASS |
|---|---|---|
| ☐ 1 | Открыть свежий проект, выбрать ML-only, пройти Setup; проверить 390px и desktop. | Нет ложного требования LLM key, формы не выходят за экран; Save не выдаётся за Ready. |
| ☐ 2 | Изменить Settings; проверить сохранение и отклонённое значение. | Ошибка видна, неподтверждённое сохранение не становится успешным; login не использует несохранённый URL. |
| ☐ 3 | Добавить/refresh RSS, открыть Today, запустить допустимый backlog. | Пусто/ошибка/offline различимы; статус нужного job находится в Today, не в чужом Ops monitor. |
| ☐ 4 | Открыть paper/Reader; затем stale/missing-output сценарий на копии. | Есть понятный rebuild; старые HTML/figure не выдаются за текущие. |
| ☐ 5 | Набрать заметку, попытаться уйти: отменить, затем подтвердить. | Отмена сохраняет черновик; уход не делает скрытый Save. |
| ☐ 6 | Сохранить вопрос без PDF; отдельно попробовать Ask при отсутствии источника/модели. | Вопрос остаётся сохранённым; typed failure/abstention виден, нет немого исчезновения. |
| ☐ 7 | Изменить tag/verdict, проверить ошибку и отказ force. | Нет потери нового текста/рационала и ложного ACK; нет автоматического повтора native-write. |
| ☐ 8 | Search/Related/Discovery: раскрыть длинное evidence, явно Add одну тестовую статью и reload. | Полные IDs/цитаты доступны; подтверждённое «In library» не откатывается старым статусом; согласие на private context отдельно. |
| ☐ 9 | Pending: отфильтровать и выбрать изменения; применить один безопасный change на копии. | Подписи полей доступны, подтверждение относится к выбранным ID; backup и реальное состояние в Zotero проверены вручную. |
| ☐ 10 | Синхронизировать working set, отключиться, сохранить изменения, перезапустить и reconnect. | Device queue видна до ACK; конфликт требует выбора; нет дубликатов из автоматического replay. |
| ☐ 11 | Открыть Ops status recovery и Weekly download. | Retry только читает статус; не повторяет retrain/generation. Отчёт скачивается без запуска нового обзора. |
| ☐ 12 | Проверить UNKNOWN local readiness и границы недоступных функций. | Защитный отказ понятен; недоступные model/account/private-input возможности не выглядят успешно проверенными. |

Фиксировать environment, revision, действия, expected/observed result и screenshot
для каждого FAIL; только человек после этого отмечает пользовательскую приёмку.

## Повторение автоматических проверок и provenance

Базовые команды проекта: `pre-commit run --all-files`, `pytest -q --forked`,
`npm test --prefix frontend -- --no-file-parallelism --maxWorkers=1 --minWorkers=1`,
`npm run lint --prefix frontend`, `npm run build --prefix frontend`.
Перед browser opt-ins нужен актуальный build; isolation/env/SDK bootstrap описаны
в [tests/README.md](../../../tests/README.md). Длинные локальные процессы запускать
под memory guard, не загружать резидентную модель и не убивать чужие процессы.

Исходные фактические команды использовали bounded harness, owned HOME/TMP/Settings,
сериализацию и memory guard. Это не утверждение, что голый `make check` или
production smoke был исполнен над личным project root. CLI app-construction smoke
для публикации отдельно прошёл на disposable project: `ok=true`, `route_count=133`,
без lifespan/server/model startup. Первоначальная попытка `python -m` была отклонена
до работы (у пакета нет `__main__`); использован настоящий установленный CLI,
без изменения приложения или ослабления проверки.

- [results.json](results.json): machine-readable counts, limits, 12 remaining IDs,
  логические имена исходных JUnit/Vitest артефактов и SHA256.
- [source-manifest.json](source-manifest.json): SHA256 проверенных runtime/test/config
  файлов; `null` сохраняет факт намеренно удалённого legacy-теста. Публикация должна
  сохранить эти байты, а не выдавать прогон для старого кода за проверку нового.
- [findings.json](findings.json): все 67 исходных записей и явное родительское решение.
- [coverage.json](coverage.json): 25 канонических возможностей и исполненные owners.

Raw logs, локальные пути, профили, базы, PDFs, secrets и model artifacts в Git/PR не
загружаются. Хеши — указатели на сохранённые локальные receipts, а не притворные
скачиваемые вложения и не самостоятельное доказательство истинности утверждений.
Сгенерированные screenshots не объявляются все просмотренными.
