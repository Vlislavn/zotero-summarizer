# services/library — Stage-2 reading + feed review

Once papers are in your library, this domain ranks what to read next and powers
the deeper review/annotation surfaces, plus the Phase 1.14 feed-review queue.

```
unread library items ─reading_queue→ ranked "Read next" (gate score + reason)
        click ─> deep_review ─┬─ quality_review  (referee-grade digest, 11-part)
                              ├─ quality_eval     (reference-free 3-band FLAG/NEUTRAL/HIGHLIGHT)
                              └─ _paper_goal_summaries (per-goal hybrid retrieval → grounded summary)
        review_fleet ─> pre-decide a ProposedVerdict for the top-N (Confirm/Override, no LLM)
        paper_render ─> _paper_read_brief: at-a-glance Goal Match Board + Quality Panel (iframe)
        border_cache: cached active-learning "border" picks for Annotate
   feeds awaiting review ─review→ approve / reject / relabel ─> golden + pending
   review_detail: uniform "why this score?" payload for /api/golden/review-detail
```

**Goal-aligned brief (deep_review enrichment):** for each requested paper `deep_review`
runs three independently-skippable layers over the extracted text — the digest
(`quality_review`), a reference-free **quality verdict** (`quality_eval`), and **per-goal
grounded summaries** (`_paper_goal_summaries`) — and caches `{digest, quality, goal_summaries}`
in `deep_reviews.json`. The render reads them back and `_paper_read_brief` paints, in
**decision order**, the read verdict — the **diagnosis** (high writing friction or flagged evidence caps
automatic reading at a targeted skim; idea/evidence/writing stay separate) → a single **evidence-grade gauge** (the quality band
as a calibrated needle on an eosin→hematoxylin scale — it *owns* the band reading, replacing the old
Rigor+Relevance chips) → a 6-cell goal board that is the **single home of per-goal relevance**
(HIT/MISS/NOT-RETRIEVED; a fired+relevant cell is **stained** and tethers its grounded summary to its
supporting quote, surfaced inline, plus key sections) → a **self-explaining Quality panel** (plain-language
band gloss + a one-clause "how we judged it" method line + an N-of-M self-consistency count + a
legend + the decisive signals, red flags first; the full rubric sits behind one disclosure). The
brief is a triage aid, **not** a copy of the paper — the full body is not embedded; the digest is
collapsed by default. A failed layer degrades to no panel, never blocking the digest.

**Model tiering (static, per task identity):** only the digest needs the strong reasoning model (with
`enable_thinking` following the deep_review provider's `thinking_effort` — `off` disables it). The
known-cheap sub-calls — `quality_eval`'s rubric/overstatement/self-verify and the section one-liners —
ride the **feed** client (`llm_map`), routed via `ExtraLayersCtx.llm_light`; goal summaries stay on the
strong model (measure before downgrading). Falls back to the digest model when no distinct feed model is
set. This is the SOTA static per-identity tiering pattern (claude-code `model-tier-routing`), not a
difficulty router — no new config, reuses the existing `feed` stage.

The capped deep-review QUALITY lift (`rank_blend.quality_bonus` via `_quality_bonus`; grade-only default, band-primary a measured arm selected by the shared `_common.band_primary_enabled`) is added in `_blended_sort` so high-quality reviewed papers float up within a band. **Quality → must_read PROMOTION** (`rank_blend.promote_band`, OFF by default via `_common.quality_promote_enabled` / `ZS_QUALITY_PROMOTE`): the gate's compressed regressor never reaches the must_read band (≥4.5) on its own (0/69 must recall), so `_build_recs` lifts a grade-A/B ∧ goal_sim≥floor ∧ gate-relevance≥should-band paper to `must_read` — the band the gate can't reach (the inverse of the auto_quality hide gate; one band up only, never invents must from dont; absent signal → no promotion; user verdicts still win). Order-only otherwise — banding/tags stay from the gate score. Each record also carries display-only **filter facets**: `venue` (journal, from the reader), `prestige_evidence` + `max_author_h_index` (the broadened prestige-filter signal, see `_score_distribution`) — and the Zotero-column **sort fields** `publication_date` / `date_modified` (plus the existing `date_added`) for the client-side Library sort (`frontend/src/utils/relevanceBands.js:sortQueue`) |
| `_search.py` | Library **hybrid search** ("Meaning" mode): BM25 (`corpus_bm25`) + dense cosine (`corpus_read.query_affinity_for_items`) fused via Reciprocal Rank Fusion, then a local cross-encoder reranks the top-100 → top-50. Degradation ladder: rerank → (model loading/off) fusion → (no BM25) dense-only → (corpus off) empty (caller falls back to substring). `order_unread_semantic` is the thin seam `reading_queue` calls. Order + `search_score` only — gate relevance/banding untouched |
| `reading_queue.py` | rank library rows by a gate-relevance × goal-similarity blend (see `_ranking`); `semantic=true` + a `search` query instead ranks by **hybrid search** (`_search`) — only the ORDER changes (relevance/bands/histogram stay), substring is bypassed (collection/tag kept), result capped to the reranked top-50, response adds `semantic`/`reranked`/`reranker_loading`/`semantic_unavailable`; hide read items; de-dup duplicate copies (across the read+unread split); expose the score `distribution` (Library histogram, `by_band` quality-floored) + `read_score_cache_with_staleness` (relevance+prestige+gate-staleness) + `prestige_floor` (re-exported from `_score_distribution`). The displayed queue now ranks the **WHOLE library** (via `get_all_items`, normally `include_abstract=False`; offline snapshots opt in to a bounded preview; `limit` caps the returned list, the frontend reveals it incrementally), and the score **cache is global**: a Rescore (`_compute_scores_into_cache`) scans the whole library (read + unread; no-abstract items skipped) and now also stores each item's **`goal_sim`** (goal-text similarity) in its cache entry, so opening the queue reads it straight from the cache instead of re-running the corpus matmul every load — `_ranking.sort_unread` does a live `_goal_affinity` lookup only for scored rows still missing it (legacy/just-triaged); like the relevance score, `goal_sim` refreshes on the next Rescore. A full Rescore **overwrites the existing cache in place** (batch-by-batch; the old score shows until replaced, and a mid-run crash keeps the old scores — it used to wipe up front, leaving the queue unranked for minutes and truncated on failure), purging departed items only after the pass completes; the handled-filter reads verdict **priorities** via the **uncapped** `list_label_verdict_priorities` (a capped fetch silently un-hides handled papers once the table outgrows it — the 500-cap-training failure class). Only a `dont_read` verdict hides a paper; a POSITIVE verdict (`must`/`should`/`could_read`) is a reading INTENT so the paper STAYS in the queue and `_ranking.sort_unread` **pins it to the top** in priority order (a label makes a paper findable, never vanishing — surfaced to the UI as `user_priority`). Scoring runs only on refresh; the cheap `is_running`/`last_error` seam backs the `reading-queue/status` poll so a Rescore doesn't re-read the library every tick. Each row also carries the review-fleet's `proposed_verdict` (one `verdict_store.read_all()`, lazy-imported to avoid a load cycle) — **display-only**, deliberately NOT fed through `_verdict_priorities`, so a `dont_read` SUGGESTION never auto-hides a paper |
| `_score_distribution.py` | pure histogram + prestige-floor helpers (`prestige_floor` = median of KNOWN prestige, where "known" = OpenAlex returned a field-normalized `citation_percentile`; cold-start/uncited → unknown → never floored). Split out to keep `reading_queue` ≤500 LOC; re-exported there. NB a cold-start paper may now show a *provisional* author-based prestige badge (`scoring_from_prediction` surfaces `cold_start_prestige`) yet still counts as UNKNOWN to the floor (`known` keys off `citation_percentile`), so it is never demoted nor pollutes the median. `entry_prestige_evidence` returns `(max_author_h_index, evidence)` where `evidence` = citation percentile **OR** author h-index present — this is the **FILTER** signal (`_build_recs` surfaces `prestige_evidence` + `max_author_h_index` per row) so an uncited preprint by a high-h-index author is filterable as prestige; deliberately BROADER than the citation-only banding floor, which stays conservative |
| `score_tags.py` | `sync_rel_tags` — write `zs:rel/<band>` relevance tags onto scored library items so you can FILTER by relevance in Zotero (one backup; quality-floored; never touches priority/manual tags). `sync_score_ranks` — stamp a **whole-library** rank into Zotero Call Number (`zr0001…`, via the `set_field` write) for EVERY paper (scorable first, no-abstract last; no dedup) so you can SORT your entire library by relevance in Zotero (tags only filter); **idempotent** — an item whose Call Number already equals its computed `zr####` is skipped (the rank counter still advances, keeping numbering dense), so a re-run on an unchanged library writes nothing instead of re-stamping every item (a no-op `set_field` touches `dateModified`/version → a full-library phantom sync); the order is the **same relevance × goal × prestige blend the Library queue displays** (prestige used to be dropped from the records — the stamped order silently diverged; fixed 2026-06). **Both syncs refuse stale scores** (`read_score_cache_with_staleness`: cache computed by a previous gate → "Rescore first" message, never a silent stale write — the retrain→rescore→sync sequencing is enforced by the system, not the user's memory); backup-first; whole library via `get_all_items` |

| `deep_review.py` | on-demand full-text deep review of top picks; per item runs `quality_review` (digest) + `quality_eval` (quality verdict) + `_paper_goal_summaries` (per-goal board) as **independently-skippable** layers (a failed layer logs + degrades, never blocks the digest), caching `{digest, quality, goal_summaries, section_overlay, code_link}` (`section_overlay` locating findings onto the paper's own sections — see `_review_section_overlay`; `code_link` the validated GitHub repo — see `_code_link`). Loads the library-wide `prestige_floor` once per job (`_load_prestige_context`) for the asymmetric HIGHLIGHT bar. After each item, auto-rebuilds the paper-brief artifact so the board is baked in. A per-item failure is logged + skipped (partial runs stay `ready` — empty results are valid), but when **every** item raises and nothing is cached (e.g. the resolved `deep_review` LLM endpoint is unreachable), the job finishes with a **job-level `error`** (`_summarize_errors`) instead of a silent `ready`, so the UI surfaces the cause rather than showing an empty brief. The "endpoint … may be unreachable" hint is appended **only** when the per-item error actually looks like a connectivity failure (`_looks_like_connectivity`); a parse/validation error — where the endpoint clearly responded with a bad body — is reported verbatim rather than mislabelled a network outage. A digest that comes back as a raw string instead of a `PaperDigest` (onprem's parse-failure fallback) is salvaged with `extract_json_blob` in `quality_review.assess_digest`, raising cleanly on a truly empty completion rather than crashing on `.model_copy()`. Concurrency is **per-item jobs over one provider-aware pool** (mirrors `paper_render`): each requested paper is its own `_JOBS[item_key]` entry run on a shared `ThreadPoolExecutor` sized by `deep_review_fleet_concurrency` (local→1, so a 2nd paper QUEUES; remote→`max_sub_concurrency` else `_MAX_CONCURRENT`, so papers run concurrently). So you can deep-review a 2nd paper while a 1st runs; re-submitting a paper already running is a no-op (per-item single-flight); cache writes go through a locked `_write_one` merge so concurrent workers never clobber each other. `status(item_key)` reports THAT paper's job (each panel sees its OWN progress); `status()` with no key is an aggregate ("is any review running?") that the `university_access` gate + the review-fleet poll rely on. `start()` still returns `accepted` (now always `True` — there's no global slot to reject) for the review-fleet's poll contract. Each review threads a `ReviewReporter` (`_deep_review_progress`) so the polled `status().progress` carries the live phase + sub-step (e.g. `quality_rubric 2/3`, `goals 1/6`) and INFO logs time each phase with a `[dr item=KEY]` prefix — a ~10-LLM-call review is no longer an opaque spinner. Cost is **tier-aware** (keyed on the resolved provider's `lean_deep_review` flag — NOT `is_local`, since MLX is loopback yet fast): a provider flagged `lean_deep_review` (ollama, prefill-bound) uses `quality_review.lean_max_text_chars` + `lean_self_consistency_runs` + batched goal summaries (~4 LLM calls instead of ~11, ~1.5–2 min), while every other provider — incl. MLX — uses the full `max_text_chars` + `self_consistency_runs` + per-goal summaries. The lean→full switch (text cap, rubric runs, AND goal batching) is gated identically in the background job and the `verify-deep-review` CLI. The **N papers** of a batch (the fleet / prewarm pass) fan out via `_common.deep_review_fleet_concurrency`: **serial on a local provider** (one model load at a time, RAM safety), **parallel on a remote one** capped by the provider's `max_sub_concurrency` (else all N) — deliberately NOT the global `TRIAGE_JOB_CONCURRENCY` (a local-RAM triage knob), so a remote 5-pick batch isn't silently throttled to serial when that knob is `1`. Orthogonally, **sub-call concurrency** (the N self-consistency rubric samples + the per-goal summary calls) runs them **in parallel on a remote provider** — capped by the provider's `max_sub_concurrency` (default `TRIAGE_JOB_CONCURRENCY`) — and **serial on a local one** (RAM safety), via the shared `_common.deep_review_sub_concurrency` helper used by BOTH the job and the CLI so they can't drift (peak concurrent calls = papers × sub-calls, both bounded by `max_sub_concurrency`). On a slow remote *reasoning* model (~30–75 s/call of thinking) this is the dominant win: ~11 serial calls collapse toward `extract + digest + max(rubric) + overstate + max(goals)`, with **identical prompts/aggregation** (speed only, no quality change). **Per-phase thinking:** the DIGEST runs with reasoning ON (`resolve_stage_client("deep_review", enable_thinking=True)` → `llm_digest`), while rubric/overstate/goals keep the provider's fast thinking-OFF default — a benchmark vs the pinned 397B judge (`tools/bench_deep_review.py`) showed a thinking-OFF digest goes near-empty or hallucinates numbers, while the trivial calls don't need reasoning (overstate 165 s→4 s). On a remote reasoning model this lands a faithful, complete `--with-goals` review in ~60 s. `_review_one` reviews from `item['pdf_path']` when set (the review-fleet's `pdf_overrides` — an acquired cache download) ELSE the Zotero attachment `detail['pdf_path']`, so a verdict needs no Zotero write. `start(..., acquire_missing=True)` (the **per-paper button**, route-scoped to a single key) makes a worker fetch a PDF via `_pdf_acquire.acquire_for_item` FIRST for a pick with no local Zotero PDF, then review from it — so opening a paper with no attachment fetches the full text instead of showing `needs_pdf`; the acquire runs inside the per-item boundary (a fetch failure is recorded as that item's error, never swallowed) and is left OFF for the fleet (it pre-acquires + passes `pdf_overrides`). When the fetch is DECLARED-but-gated, the worker threads the acquire result's `needs_login` + `login_url` onto the cached entry so the pane shows a click-to-open sign-in link instead of a misleading generic "no full text". The three enrichment layers live in `_deep_review_layers.py` (split out to stay under the 500-LOC cap). `start(..., reader=…)` overrides the resolved library reader — the IN-PLACE Today review (`_tick._auto_review_slate`) passes an `AppLibraryReader` so a feed candidate resolves by `stable_feed_key` even when a live Zotero reader is present (caches the review under the feed key, NO Zotero write). The cache I/O primitives now live in `_review_cache.py` (re-exported here) |

| `_review_section_overlay.py` | `build_section_overlay(sections, quality, goal_summaries, *, section_summaries=None)` — locates the deep-review findings onto the paper's OWN `sections` (the `extract_pdf_content` list the quality/goal layers already grounded against), so a `section_id` is a **stable join key by construction** — never a substring match into a different extractor's text (the unreliable read-time approach the adversarial review rejected). | `review_fleet/` | **Phase-2 background fleet** that PRE-DECIDES a reading verdict for the top-N Read-next picks so the human only Confirms/Overrides. It writes **only** that sidecar — never `label_verdicts`, never Zotero. `prewarm.schedule_on_startup` (sibling of `deep_review_prewarm`; env override `ZS_REVIEW_FLEET_PREWARM_K`) kicks it off at boot.
